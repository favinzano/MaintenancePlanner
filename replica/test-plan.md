## Current-pass QA note

This pass reused the initial empty analysis as `QA Sample Pump 001`, with a clearly marked synthetic PM `QA ONLY - Non-operational placeholder` that remains Draft. It also created `QA ONLY SAMPLE EQUIPMENT - ` followed by 33 X characters (60 characters total), which is at Evidence, and `QA ONLY - Start and API error test`, which is at Asset Proposal. Those two later analyses are labeled QA-only. No QA analyses were deleted. The expired-token check temporarily created a confirmed Auth-only QA identity, sent no email, created no PlannerMC profile or analysis, and deleted that identity after the test. The project JWT lifetime was temporarily changed to 300 seconds for token issuance and restored to 3600 seconds; a read-back confirmed the restored value. No independent SQL query or exact planner-row count was run.

## To check

- Decide whether empty analyses should be persisted before intake details and whether intake should warn before losing unsaved fields on reload. These are observed product questions, not confirmed bugs.
- The browser client's automatic refresh/sign-in transition after a genuine token expiry was not exercised. The API save route was tested with a genuine expired signed JWT, and the existing save error path was inspected; the network-failure UI branch was separately exercised in F01-E5a.
- Valid approval and clipboard behavior passed in isolated local mode. They have not been repeated against hosted development; the negative approval guard was exercised there, and no hosted clipboard write was made.
- The automated suite covers the source-to-draft flow, required intake validation, incomplete-approval rejection, valid local approval, and local clipboard copy. It does not exercise Supabase authentication refresh or valid approval/copy against hosted development.

## Exclusions

Manual upload/OCR, external research, technical-content generation, voice, CMMS writes, inventory, and scheduling are explicitly unavailable or out of scope in this build and were not tested.
